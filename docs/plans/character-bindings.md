# 绑定按整套模型生效

状态：已实现（2026-10-29），2.6 的副模型部件列表除外。改动范围：`Presets.lua` 的绑定解析、`API.lua` 的绑定读写命令、
`Sculpt.rebuild` 的预设来源、`ActorInstances.lua` 的实例绑定、预设页，以及 `shape-key-system-api.md` 第 9 节。

## 1. 问题

### 1.1 现象

鬼武者里，把 ShinanoObsidian 捏脸归零并保存后，重进游戏，除头部外的部件恢复成另一套捏脸值。

当时 `user/musashi/` 下有两份绑定：

| 文件 | 层级 | `sculpt` |
|---|---|---|
| `user/musashi/Head.json`（预设页"写入绑定"按当前部件生成） | 部件自己 | `ShinanoObsidian` |
| `user/musashi/musashi.json`（10 月 15 日的旧文件） | 模型代表 | `ShinanoOC` |

`Presets.resolve_binding` 对每个部件单独解析：`Head` 命中部件自己的文件，`OniHead`、`Body`、`Cloak` 等没有自己的文件，
回退到模型代表，命中 `musashi.json`。`Sculpt.rebuild` 按部件取预设，于是同一个角色同时用着两份捏脸预设。
编辑期间所有键都被手动改过（`touched`），两份预设的分歧不可见；重进游戏后未改过的键重新按各部件的预设取值，分歧才显现。

预设页只显示"生效的绑定"（各部件命中结果里最具体的一个，即 `Head.json`），不显示其他部件实际用的是哪一份。

### 1.2 根因

绑定的解析单位是部件，编辑和保存的单位却是整个角色：

- 捏脸键按键名合并，一个滑块同时作用于所有带这个键的部件（`Sculpt.rebuild`）；
- 表情配置、增益、视线只对脸生效，一个角色只有一张脸；
- `save_sculpt` 保存的是整个角色的值；
- 写绑定的入口却有两种单位：`write_binding {part}` 写部件自己的文件，`bind_config` 和 `save_tuning` 写当前生效绑定所在的那一级。

只要同一模型下同时存在部件级和模型级的 `user/` 文件，角色就会分裂。鬼武者的适配文档（`onimusha-adapter.md` 4.3）
本来要求"绑定按角色，不按部件"，但 Core 的解析链仍保留了"部件自己"这一级，适配器无法关掉。

### 1.3 按部件绑定的实际用途

按部件绑定源自荒野：猎人由五个部位拼成，每个部位是独立 mesh，可能来自不同 mod。实际情况：

- 荒野 `mods/` 下的绑定全部是代表部件（2 号部位）的文件，没有 mod 为单个部位单独提供绑定；
- `user/` 下出现的部件级文件，都是预设页按当前部件写出的，例如 `user/ch03_032_501/ch03_032_5014.json`，
  它和同模型的 `"global": true` 文件并存，后者生效，前者不起作用；
- 同名键要在不同部件上取不同值的需求，已经由捏脸预设的 `overrides[part]` 表达，不依赖部件级绑定；
- 混搭（各部位来自不同模型）时，部件级绑定也没有解决"整个角色用哪套表情配置和增益"的问题，
  仍然要靠"取最具体的一个"来挑。

部件级绑定的收益只剩"为单个部位换一个捏脸预设"，没有找到依赖它的场景。代价是四级解析链（global / 部件 / 模型 / default）
乘以两个来源、`global` 字段、`scoped_bindings` 下的排序分支，以及 1.1 这类不可见的分裂。

## 2. 方案

### 2.1 绑定单位

**一个角色同一时刻只有一份绑定。** 绑定按模型存放，文件仍是 `<src>/<模型>/<代表部件>.json`，
mod 现有的文件格式和位置不变：

| 游戏 | 模型（`A.model_of`） | 代表部件文件 |
|---|---|---|
| 荒野 | `ch03_012_001`（套装） | `ch03_012_001/ch03_012_0012.json` |
| 崛起 | `f_279` | `f_279/f_body279.json` |
| RE4R / RE9 | `leon`、`ada` 等角色 | `leon/leon.json` |
| 鬼武者 | `musashi` | `musashi/musashi.json` |

解析链缩短为三步，每步先 `user/` 后 `mods/`：

1. 主模型的代表部件文件；
2. `default.json`；
3. 都没有：用 `settings.json` 的全局设置。

部件级文件（`<模型>/<非代表部件>.json`）不再参与解析。`global` 字段失去意义，读取时忽略，写入时不再生成。

### 2.2 主模型

角色身上的部件可能来自多个模型（荒野混搭）。主模型是**所穿代表部件所属的模型**：荒野、崛起为身体部位，
鬼武者、RE4R、RE9 的所有部件本来就归同一个角色模型。混搭者通常把关键形态键放在身体部位上，所以身体决定整个角色。

所穿部件中没有代表部件（例如身体部位没有形态键，未被扫描到）时，取所穿部件通道数之和最多的模型。

主模型的绑定决定整个角色的表情配置、增益、视线、条件规则和捏脸预设。主模型没有任何绑定时直接用 `default.json`，
不再去副模型里找。

`scoped_bindings` 的现有规则（用户来源优先、模型指纹匹配）只在同一模型的 `user/` 与 `mods/` 之间起作用，
即 2.1 每一步内"先 `user/` 后 `mods/`"和指纹检查，合并后这个开关只保留"`eyes.neutral` 随绑定保存"的含义。

### 2.3 捏脸值

每个角色只有两份捏脸预设参与计算：

- **当前值**：主模型绑定所选的预设（`user/` 优先）；
- **默认值**（"恢复默认"、A/B 预览）：主模型 `mods/` 绑定所选的预设。

混搭时，其他模型的 mod 也可能为自己的部件提供捏脸默认值。处理方式：

- 其他模型 `mods/` 绑定所选的预设，只对**那个模型的部件**、且只对**主模型两份预设都没有提到的键**提供默认值；
- 它不进入当前值的来源，也不会被写回；用户保存时，这些键的当前值写进主模型的预设。

这样，混搭进来的部件保持其 mod 作者给的外形，用户一旦保存，结果完整落在一份预设里，下次加载不依赖副模型的文件。

同名键在不同部件上取不同值，继续用预设里的 `overrides[part]`。

### 2.4 写入

所有写绑定的入口都写主模型的代表部件文件：

| 入口 | 现在 | 改后 |
|---|---|---|
| 预设页"把当前表情、捏脸配置和增益写入绑定"（`write_binding {part}`） | 当前部件自己的文件 | 主模型文件 |
| "绑定到 …"（`bind_config`） | 生效绑定所在的那一级，没有时写代表部件 | 主模型文件 |
| "保存到绑定"（`save_tuning`） | 生效绑定所在的那一级 | 主模型文件；生效的是 `default.json` 时仍写 `default.json` |
| "恢复 mod 自带的绑定"（`restore_mod_binding {part}`） | 部件自己的 user 文件 | 主模型的 user 文件 |

`write_binding` 的 `part` 参数保留，用来定位模型，不再决定文件。

### 2.5 旧文件迁移

`user/` 下残留的部件级文件不自动合并，因为无法判断它和模型级文件哪份是玩家想要的（Lua 读不到文件修改时间）：

- 扫描时发现主模型下有部件级 `user/` 文件，提示一次：`<路径> 是旧的部件绑定，已不再生效`；
- 预设页的绑定区列出这些文件，每份提供两个操作：
  - **用它替换整套绑定**：把文件内容（去掉 `part`、`global`）写进主模型文件，然后对旧文件写删除标记；
  - **删除**：写删除标记。
- 主模型没有 `user/` 文件、只有一份部件级 `user/` 文件时，同样只提示，不自动接管。

`mods/` 下的部件级文件同样忽略并提示一次；目前没有已知 mod 提供这类文件。

### 2.6 预设页

- "生效的绑定"显示主部件和主模型的查找过程。混搭时"副模型提供默认值的部件"暂不单独列出。
- 绑定区列出 2.5 的旧文件。
- "绑定到 …"的显示名用模型名（`armor_name` / `character_names.json`），不再出现部件 id。

## 3. 不变的部分

- 文件格式 `sks.binding/1`、`sks.sculpt/1` 不变，`mods/` 现有文件无需修改。
- 指纹检查不变：`mods/` 绑定的 `fingerprints` 与所穿 mesh 不符时跳过，`user/` 不检查。
- 捏脸预设的查找顺序不变：先找主模型文件夹，再找通用预设。
- 删除仍写删除标记。
- 手动选择的配置优先于绑定，直到换装，规则不变。

## 4. 实现步骤

1. `Presets.resolve_binding(model, only_source, fingerprints)`：按 2.1 的三步解析，返回值保留 `chain`、`hit`、`source`、`data`、`folder`，
   去掉 `level` 中的 `global` / `own`。新增 `Presets.legacy_part_bindings(model, parts)` 列出 2.5 的旧文件。
2. `API.resolve_bindings`：先按模型分组，按 2.2 选主模型，`C.binding` 为主模型结果；`C.part_bindings` 改为 `C.model_bindings`，
   只供 2.3 的副模型默认值使用。
3. `sculpt_presets_of(part_id)`：返回主模型的当前预设和默认预设，外加该部件所属副模型的 mod 预设；
   `Sculpt.rebuild` 的默认值取"主模型 mod 预设 → 副模型 mod 预设 → 0"。
4. `bind_target`、`write_binding`、`save_tuning`、`restore_mod_binding` 按 2.4 改写入目标。
5. `ActorInstances.binding_of` 换成同一套模型级解析。
6. 预设页按 2.6 调整；新增文本补 `en.json`。
7. 更新 `shape-key-system-api.md` 第 9 节和各适配器文档中关于绑定层级的描述；`unreleased.md` 记一条不兼容变更
   （部件级绑定不再生效）。

## 5. 测试

在 `tests_bind` 一组中补充：

- 1.1 的复现：模型级 `user/` 文件选 A、部件级 `user/` 文件选 B，所有部件都取 A，并产生一次旧文件提示；
- "用它替换整套绑定"后，所有部件取 B，旧文件变为删除标记；
- 荒野混搭：主模型由 2.2 选出；副模型 mod 预设只为自己的部件、只为主模型未提到的键提供默认值；保存后这些值进入主模型预设；
- `write_binding {part = 非代表部件}` 写入主模型文件；
- `mods/` 指纹不符时跳过，回退到 `default.json`；
- 背景角色（`ActorInstances`）与编辑角色得到相同的主模型和预设。
