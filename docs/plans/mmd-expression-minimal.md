# MMD 表情：保下限方案（SKS 内置 mmd 配置）

目标：任意 PMX 脸原样导出（不在 Blender 里改键），SKS 用一份内置配置 `mmd.json` 自动找到能用的键，做出合格的眨眼、口型、眉眼动作。不追求还原 MMD 的全部表情。

决定（用户 2026-10-10）：不给 Blender 端加工具，兼容全部放在 SKS 的预设里；以基础动作（上眼皮、嘴角、张嘴、眉）为主，不用整套情绪预设键。

## 1. 实测依据（2026-10-10，6 个 PMX 模型：Anon、PEKORA、白希1.0、绯英、莉奈娅、菲娜2.0）

| 发现 | 对运行时的影响 |
|---|---|
| 不带后缀 = 模型自己的左侧，6/6 一致（ウィンク 质心 x>0） | 与 SKS 的 L = 脸自己的左侧一致，直接按名字对应 |
| 「右」后缀不一定是侧别（绯英 怒り右 在中线附近） | 只对眼睛和嘴角的固定候选名认侧别；眉毛只用对称键 |
| PEKORA 的 wink 编号与标准相反 | 运行时选错只会变成笑眼形状的眨眼，仍然是闭眼 → 下限可接受；需要时用每个部件的覆盖修正 |
| 白希、菲娜 的 まばたき 只是组合形态，没有顶点键 | 眨眼优先用左右 wink 对，まばたき 只做兜底 |
| 写法变体：２/2、ｳｨﾝｸ/ウィンク、狭く/狭め/缩げ、末尾空格 | 名字匹配前做宽窄统一 |
| 脸上的形态键全部互相重叠，导出后只占 1 个 target（Shinano 脸 141 个通道已验证） | 键再多也不会碰到 27 target 上限，只影响文件大小，所以不用在导出前删键 |

## 3. SKS 改动（已实现 2026-10-10，离线测试通过，未进游戏）

1. **Profile：候选列表。** 通道字段 `"any": [...]`：同一部件上只有排名最高的那个名字驱动（通道名本身排第 0，LOD 副本一起保留）。`"unless": ["通道名", ...]`：列出的通道在该部件上存在时，本通道不驱动（まばたき、对称嘴角用它）。没有 any 的配置（ARKit 等）行为不变。实现：`Names.build_index(names, aliases, entries)` + `Names.match_part(index, names)`，Scene / 预览 / 推荐统计都改用 match_part。
2. **宽窄统一。** `U.norm` 对非 ASCII 名字先做 `U.fold_width`：全角 ASCII 转半角，半角片假名转全角（ﾞ/ﾟ 合并成浊音、半浊音），〜 转 ~，去掉全角空格。纯 ASCII 名字走原来的快速路径。
3. **自动推荐。** 不用新代码：现有的覆盖率推荐（match_count）在 6 个模型上都选 mmd。
4. **选错的键。** 用现有机制：另存一份 `extends: "mmd"` 的用户配置，改那个通道的 any 顺序，再绑定到该部件。
5. 配置文件：`data/ShapeKeySystem/builtin/profiles/mmd.json`（22 个通道）。离线测试：`tests/tests_mmd.lua` + `mmd_names.json`（6 个模型的真实键名）。

## 4. 第一步要验证的风险

日文键名能否完整走通：Blender 键名 → RE Mesh Editor 导出（UTF-8 字符串表）→ 游戏 `getBlendShapeChannelName` → Lua 字符串。拿一个模型导出，在游戏里打印通道名对照。如果这一步有乱码，再考虑导出器侧的转写方案。

## 5. 代价

只用基础动作出不来 MMD 那种雕出来的弯月笑眼；笑容只能靠闭一半眼 + 嘴角上扬。可选附加：把 笑い 映射到 cheekSquint，放进附加槽。
