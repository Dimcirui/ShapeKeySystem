# 多角色编辑

场景里同时有几个角色时（RE4R 的过场、模型鉴赏、同伴），面板可以切换「当前编辑的角色」，捏脸、表情配置和驱动都作用于所选角色。

## 角色按人认

角色是「人」，不是场景里的某个对象。适配器的 `A.actor_of(face)` 返回人的标识（RE4R：`leon`、`ada`），显示名取 `builtin/<id>/<A.model_names>` 的 `models[id]`。同一个人的所有副本（玩家、过场副本、鉴赏雕像）归为一个角色，共用一套配置。

没有 `actor_of` 的游戏只有一个角色（标识 `""`），界面不显示角色下拉，行为和以前一样。

## 编辑对象就是主角色

Core 原有一条完整的「主角色」流程（捏脸编辑、表情配置、调参、驱动、外部 API），以及一条只读的「额外角色」流程（`ActorInstances`，按各自的绑定驱动）。多角色编辑不新开第三条流程，而是让所选角色成为主角色：

- `Core/Actors.lua` 每 60 帧汇总一次角色：适配器默认主角色的头部（`A.faces(A.primary_root())`）加上 `A.additional_faces()`，按 `actor_of` 分组。玩家所在的角色标为 `player`。
- 所选角色的全部头部交给主角色扫描（`Scene.override`），根取玩家的根（玩家属于该角色时）或第一个头部的 `face_root`。所以默认情况下，玩家的过场副本也由主流程驱动，和玩家用同一套捏脸与表情。
- 其余角色的头部交给 `ActorInstances`，按各自的绑定驱动；玩家不是所选角色时，玩家也在其中。
- 所选角色不在场时，回到玩家所在的角色；所选标识保留，再出现时恢复。
- 切换角色前，捏脸有未保存的修改或映射有未保存的修改时拒绝切换，提示先保存或撤销。
- 释放事件（过场、换装、雕像切换）清空 `Actors` 缓存的头部引用，和 rig 一起放掉。

条件规则、自动表情、面捕、互动和录制回放仍作用于主流程，也就是所选角色；它们的输入（血量、手机数据）仍来自玩家。后续再加「作用于哪个角色」的选项。

## 驱动

每条驱动带 `actor`（角色标识）。新建的驱动属于当前编辑的角色；驱动页只列出当前角色的驱动，其他角色的驱动照常在后台运行。

- `actor` 是当前编辑的角色：照旧以外部值（所有者 `drivers`）写入主流程。
- 其他角色：值放在 `Drivers.actor_values[actor]`，由 `ActorInstances` 写入：表情配置里的通道覆盖该槽位（不与捏脸基值混合），其余同名形态键直接写网格。
- 旧文件里没有 `actor` 的驱动属于玩家所在的角色（`Drivers.default_actor`）。

## 界面

标题栏左侧在标题后面放角色下拉「编辑：里昂（玩家）▾」，只有一个角色时不显示。各页都编辑所选角色，页面布局不变。

`state.actors`：`list = {{id, name, player, copies}}`、`selected`（实际在编辑的角色）、`wanted`（用户选的角色，可能不在场）。命令 `select_actor {id}`。
