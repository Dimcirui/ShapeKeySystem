# 性能优化维护说明

## 目标查询

条件表情和面部互动按归一化名称建立目标索引，每次更新复用活跃层顺序，
使逐键查询的开销随查询键数和活跃层数增长，避免每个键扫描全部目标。
名称碰撞保留全部目标及源表顺序；配置替换、拖拽修改和重置必须使对应缓存失效。

## 录制准备

录制校验和分析通过可取消任务分片推进，完整校验两条轨道后才连接游戏对象。
分片减少单次回调集中工作，不保证总准备时间缩短；时间预算在检查点生效，
受时钟分辨率、GC 和检查点间隔影响，不是硬实时上限。

连续空差分共享只读快照，非空差分复制后修改。共享快照的统计按重复帧数累计，
不能改写前帧，也不能遗漏实际经过帧的命中次数。
只为选中轨道保留快照，未选轨道仍须完整校验。
持续变化的录制仍保留完整变化帧；文件读取、JSON 解析、游戏对象连接和绑定刷新仍同步执行。

播放状态和性能指标的接口约定见 [shape-key-system-api.md](shape-key-system-api.md)。

## 离线复测

需要 Python 和 `lupa`，在仓库根目录运行：

```powershell
python tools/profile_offline.py
```

结果默认写入 `local/performance/latest.json`，该目录由 Git 忽略。
需要保留不同版本结果时指定文件名：

```powershell
python tools/profile_offline.py --output local/performance/baseline.json
```

工具使用实际 Lua 模块和项目的 REFramework 替身，文件操作位于临时目录，不连接游戏。
查询与解码预热后测量五轮中位数；准备任务另测分片数量和最大分片耗时。
分配量与保留内存分别测量，分配量不能解释为泄漏。

对比时保持机器、录制、参数数量和测量条件一致。替身耗时不包含真实 SDK、渲染器或 GPU 开销，
不能换算为游戏 FPS；引擎调用次数仅用于定位重复操作，不能据此删减对象和索引校验。

## 游戏内验证

进入存档后测试条件渐变和面部拖拽，再播放录制，检查准备进度、暂停、跳转、循环和停止恢复。
预期混合顺序保持一致，停止后游戏动画恢复，准备取消后不会出现延迟播放。
在「设置与调试 → 性能 → 展开耗时详情」观察文件读取、准备分片和原版注入的最大耗时。
异常反馈包含录制名、操作、耗时与脚本错误。
