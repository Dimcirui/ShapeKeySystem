# RE4R Leon 与 Ada 适配器

适配器接口见 `multi-game-adapter.md`，表情配置与绑定格式见 `shape-key-system-api.md`。本文记录 RE4R 的信号来源、写入方式和后续适配。

## 现状

- 游戏 id 为 `re4`，已适配里昂（Leon）与艾达（Ada）。适配器从当前玩家 context 查找头部与部件，按网格身份和通道数识别重建。
- 表情来源为面部骨骼相对中立位的位移或旋转，以及头部网格的原生修正通道权重；眼球关节旋转用于视线驱动。
- 信号字典 `builtin/re4/signals.json` 的 63 个通用信号中，39 个有映射，24 个为 `raw: null`；近似映射标为 `guessed`。
- 眼球使用 `L_Eye` / `R_Eye`，由 Core 换算视线。
- 自定义形态键在活动期间逐帧写入，归零时同步写回。
- 身体、头发和 Ada 自定义头部在扫描时补齐可写权重数量，沿用设置页的定期重扫间隔。
- 面板打开时屏蔽鼠标点击、滚轮、移动和键盘游戏命令；关闭后等待按键松开，再恢复输入。
- 提供玩家动作与血量条件、原生信号诊断录制，以及表情信号和视线回放。
- 游戏内眨眼、张嘴、眉毛与嘴角补充映射、面板操作、过场和读档正常。

### 角色与服装

Ada 按头部资源 `cha200`、`cha800`、`cha801`、`cha803` 识别，配置归入 `ada`，Leon 继续使用 `leon`。两名角色共用形态键写入、输入屏蔽、条件与录制回放；每个 rig 绑定自己的标定表。

当前服装范围为里昂的默认短袖与夹克，以及艾达的默认造型、礼服和旗袍。艾达三套造型的模型加载与形态键驱动均正常。

`builtin/re4/ada.json` 使用原版 Ada 待机采样确定中立位，嘴部位移轴按父骨骼换算。眨眼读取实际活动的 `L/R_U_Eyelid03`；`Eyelid3` 的静态姿态不参与眨眼，下眼皮挤眼使用原生修正通道。视线沿用 SKS 的眼球中立位设置。

Ada 的自定义头部在扫描时补齐可写数量，检查 MeshReady、通道数和现有列表长度，沿用额外网格的准备流程。Leon 头部继续使用游戏设置的数量。Ada 的口型、眨眼与视线已通过游戏反馈；44 秒录制中的 804 帧均保持 111 个通道、111 个可写权重和长度为 111 的列表。

### 信号

Leon 基础标定取自 [RE4R-ShapeKey-System](https://github.com/Funnyguysmz/RE4R-ShapeKey-System) 0.4.5-rc.1，保留 48 条规则，并补充 8 条眉毛与嘴角骨骼规则，共 56 条、42 项具名输出；许可见 `THIRD_PARTY.md`。

信号字典中的 39 个映射项表示通用信号与标定输出的对应关系。运行时可用输出随模型保留的原生通道而变化；本轮替换模型录制包含 24 项连续输出，其中 7 项来自新增骨骼规则。

旋转用相对中立位的四元数对数投影到标定轴，单位为度；位移投影单位为毫米。每条规则限幅后乘增益，同名输出合成后再次限幅。`jawOpen` 等标定输出作为适配器的 raw 通道，范围为 0–1，字典 `full = 1`。Core 按通用信号计算 Profile。

原生修正通道先采样，再写入自定义形态键。91 个原生名字用于哈希识别；实际采样按当前网格的通道和数组长度确定。

### 通道和写入

RE4R 的装箱元素 `ToString()` 会返回错误的数值，通道哈希改从 `get_ChannelNameHash():get_Item()` 读取。适配器通过 `hash_item_only` 选择这条路径。

网格就绪判断检查 MeshReady、通道数、权重数组长度和稳定帧数，并兼容 RE4R 缺少的可选启用标志。每帧通过 gate 和网格签名检查当前 rig，重建后重新绑定。

扫描、表情、捏脸和外部接口共同使用通道保护规则，保留游戏驱动的原生修正通道。`strict_bounds` 在读取和写入时检查当前数组边界。

游戏对照中，按变化阈值跳过写入时，眨眼过快且缺少过渡。因此当前为 RE4R 单独启用活动权重逐帧写入，后续继续改进写入策略。`rewrite_active_weights` 在当前或上次权重非零时持续写入，零到零可以跳过。荒野和鬼武者沿用变化阈值策略。

### 身体与头发

`prepare_parts(parts)` 在首次扫描、手动重扫和定期重扫时检查额外网格。沿用设置与调试页的“定期重扫”间隔；设为 0 时关闭定期检查，手动扫描仍可触发。

对于包含已识别自定义通道的额外网格，当 MeshReady、通道数稳定且现有权重列表长度足够时，通过 `set_BlendShapeChannelWeightCount` 补齐可写数量。Ada 自定义头部使用同一准备流程，Leon 头部保持游戏设置的数量。未就绪的网格在后续重扫时重试。

初始化后，表情和捏脸两条写入路径均使用 RE4R 的活动权重逐帧写入策略；重扫间隔只决定何时检查网格。

### 原生信号诊断与录制

眉毛与嘴角提供骨骼补充规则：内眉上提、左右外眉上提、左右压眉、左右嘴角下撇。对应输出没有可读的原生来源时，使用局部位置相对中立位的投影；原生来源读到零值时仍使用原生结果。多条补充规则先合并，再参与来源选择，避免与原生权重叠加。

眉毛沿面部坐标的上下方向测量，嘴角方向按 `C_Mouth` 中立旋转换算。阈值取待机活动范围外的余量，嘴角下撇限制增益。当前标定来自 Leon 的待机与过场记录；微笑、酒窝等动作继续使用原生修正通道。

设置与调试页提供录制名称、开始录制、停止并保存、记录中立位和保存快照。面板显示骨骼相对当前中立位的位移、旋转及峰值。中立位只用于诊断比较，不改写 Leon 的运行标定。

诊断覆盖标定骨骼及下巴、嘴角、眼皮、眉毛、眼球、舌头等观察骨骼，同时读取当前网格中可用的原生修正通道。记录包括局部位置、四元数、标定轴测量值、原生通道权重、归一化输出和缺失来源状态。采样在 SKS 权重写入之前执行，每次重新解析引擎对象。

录制目标为 20 Hz，最长 90 秒；实际采样时间写入每帧。角色不可用或部件身份变化时自动结束并保存。保存失败时保留当前数据，可点击“重试保存”。文件位于 `reframework/data/ShapeKeySystem/native_signals_re4_*.json`；快照为同目录下的 `native_snapshot_re4_*.json`。

### 录制信号回放

表情详情页的“面部动画测试”读取 `sks.native-signals/1`，将录制的标定输出送入当前 Profile，继续使用当前增益、平滑和捏脸基值。支持播放、暂停、跳转、速度调节和循环；停止后恢复实时信号。

录制列表包含默认诊断输出目录中的 `native_signals_re4_*.json`，以及 `user/recordings/` 下的同格式文件。新录制保存后点击“刷新列表”即可播放。

回放使用文件中已保存的输出。修改标定后重新录制，旧文件保留录制时的信号覆盖。

读取时检查游戏 id、时间顺序、0..1 信号值及角色身份一致性。存在某个信号但中途缺帧时拒绝播放，避免把读取失败当成零值；整段录制都没有的输入会列为缺失参数。眼球局部四元数换算为 SKS 视线角，继续使用当前中立位和反转设置；某侧缺少完整眼球姿态时，该侧回放视线归零并显示提示。

回放会话只保存当前玩家地址和部件签名，角色不可用或网格重建时停止。回放替换 SKS 的信号输入，不写回原生骨骼或游戏面部动画层。

### 面板输入

`Input.lua` 在 `share.hid.Device.update()` 后清理游戏托管鼠标的触发、按下、抬起、重复、滚轮和移动字段。面板从原生鼠标读取操作数据。

字段偏移由类型信息取得，并检查类型、尺寸、对象边界和重叠。设备引用保留在一次 hook 调用内。关闭面板时，等按键与抬起事件结束后恢复输入和光标模式；共用登记表协调其他面板的接管。

键盘生成的操作在 `share.hid.Command` 更新后拦截：清空触发、按下、抬起、浮点及向量等命令字典，保留命令设置和禁止项。初始化时检查字典类型和 `Clear` 方法，按类型信息枚举更新重载安装 hook。原生键盘状态继续供 REFramework 快捷键和 ImGui 文本框读取。

关闭面板后等待全部键盘按键松开，再经过两个帧边界恢复游戏命令。脚本重置时解除等待。哈希探针同时保存 `re4r_input_status.json`，记录鼠标与命令拦截次数、已安装 hook 和错误。

### 游戏状态条件

`Conditions.lua` 参考 `RE4-MODVariantManager_v0.4.2.zip` 的 RE4R 状态读取入口，接入 `A.conditions`。每次采样重新取得玩家 context，结果交给 Core 的条件表情规则、保持时间及淡入淡出处理。

支持 31 项布尔动作条件，包括战斗、瞄准、射击、换弹、招架、体术、蹲伏、移动、受伤和燃烧。另提供血量百分比、掉血与回血事件、死亡、游戏生命状态以及护甲网格存在条件。读取失败保留为未知值，正反条件均不命中。

血量来自 `get_HitPoint()` 的 `get_CurrentHitPoint` 和 `get_DefaultHitPoint`；Core 计算 `hp_pct`、`hp_decreased` 和 `hp_increased`。血量变化事件配合规则的保持时间使用。玩家身份变化时清除比较基线，避免把角色切换识别为受伤。差分管理器的 `hp_ratio` 在 SKS 中对应 `hp_pct`，其余动作条件沿用 `is_*` 标识。

`hp_vital` 读取 `getHitPointVital`，选项优先从 `chainsaw.character.Vital` 枚举取得。护甲条件只表示 `get_HasArmorMesh`，不表示角色处于战斗或穿着某件自定义衣服。

## 模型配置转换

运行 `tools/convert_re4r_profile.py INPUT --id ID --actor leon|ada --output NEW_DIRECTORY`，输出表情 Profile、名字表、捏脸预设和对应角色的全局绑定。`--actor` 默认为 `leon`。转换保留自定义形态键名，将 ARKit/MMD 映射转换为 SKS Profile 节点；运行标定由当前角色选择。

体型、服装、发型及五官造型区域的键归捏脸层，不加入表情 Profile。名字表保留全部通道和中文显示名，捏脸预设为全部通道提供初始值；面部表情键在捏脸页仍按“显示表情通道”开关显示。

旧手动叠加与当前捏脸基值重映射的差异写入转换报告。面部导航互动沿用 Core 的名字匹配，也可以通过条件集的 `interactions` 配置模型专属键名。
