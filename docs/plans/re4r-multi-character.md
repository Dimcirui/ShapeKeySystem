# RE4R 多角色扩展

第一步已完成（七个人都识别，没有标定的角色不驱动表情），第二、三步按需再做。

## 现状

RE4R 适配器按头部网格文件名的编号组认人（`cha000_10` → `cha000`），这张表与 ArmorVariantManager（AVM）的 `CharacterId.lua` 是同一套：

| 人 | 头部编号组 |
|---|---|
| 里昂 | `cha000`、`cha005`、`cha006`、`cha500` |
| 艾达 | `cha200`（本篇）、`cha800`、`cha801`、`cha803`（逆转篇 / DLC） |
| 阿什莉 | `cha100`、`cha102` |
| 路易斯 | `cha300`、`chi100` |
| 克劳萨 | `chb700`、`chi200` |
| 威斯克 | `cha600`、`chj000` |
| 汉克 | `chi300` |

差别在于 SKS 把「认出这个人」和「有表情标定」绑在一起：只有带标定文件（`builtin/re4/leon.json`、`ada.json`）的编号组才算脸（`Adapter.lua` 的 `ACTORS` → `actor_of_path` → `face_path` → `is_face`），其余五人的编号组只用来判断「这是另一个角色」（`OTHERS`）。

结果：

- 里昂、艾达（本篇 NPC 和逆转篇玩家）可以驱动。
- 阿什莉、路易斯、克劳萨、威斯克、汉克的头部被整个忽略：不只是表情，捏脸、绑定、键组、驱动、外部接口和其他插件的选择都不作用到他们身上，角色下拉里也没有他们。
- 玩家本身是这些角色时（佣兵模式的克劳萨 / 汉克 / 威斯克 / 路易斯，阿什莉章节如果玩家 context 是她），`primary_ready` 为假，SKS 对玩家完全不工作。

所以「只支持里昂」的说法不完全准确（艾达支持），但除里昂、艾达外的角色确实都不支持。

## AVM 的做法可以借用的部分

- **认人**：同一张头部编号组表，只看头部路径（身体网格随服装变化，头部不变）。SKS 已经这样做，不用改方法，只要把表补全。
- **找角色**：AVM 从 `CharacterManager.getPlayerContextRef()` 取玩家，从 `get_PlayerAndPartnerContextList()` 取同伴（路易斯、阿什莉跟随段），从 `TimelineEventPuppetChara`（`_HeadMesh` 等字段）取过场副本，从 `FigureModelController` 取鉴赏模型。SKS 现在用玩家 context + 原生插件列出的全部 Motion 网格（`sks_native.motion_meshes`）+ 鉴赏模型，已经能找到同伴和过场副本的头部，只是被 `face_path` 过滤掉了。同伴 context 列表可以作为补充：给角色列表标出「同伴」，并给同伴取根节点时少走一层路径推断。
- **标识**：AVM 的文件键是首字母大写的人名（`"Leon"`、`"Ashley"`）。SKS 用小写（`"leon"`、`"ashley"`）。两边来自同一张表，AVM 调 SKS 接口时 `actor = name:lower()` 即可，不需要再查场景对象。
- **不借用**：AVM 认不出头部时按 kind ID 和材质名相似度猜人。SKS 依赖骨骼标定，猜错会驱动错误，不跟。

## 方案

### 第一步：认出所有人，表情按有无标定决定

- `ACTORS` 合并 `OTHERS`，七个人都能被 `actor_of` 返回；`A.actor_ids` 和 `character_names.json` 补全（阿什莉、路易斯、克劳萨、威斯克、汉克）。
- 标定改为可缺：`A.init` 只加载存在的标定文件；`A.bind` 遇到没有标定的角色返回空句柄（不读骨骼、不读原生通道），**不回退到里昂的标定**——`Signals.bind` 现在缺省用里昂的数据，骨骼不同会读出错误的表情。
- 没有标定的角色：捏脸、绑定、键组、驱动、外部接口、其他插件的选择照常生效；表情层不驱动（等同表情关闭，表情配置的通道写 0 加捏脸基值）。程序化眨眼（`FacialController.BlinkRate`）和条件规则是否可用，按实现时实测结果决定。
- 玩家是这些角色时成为主角色，面板、捏脸编辑照常；条件读取的玩家血量等来自玩家 context，与人无关，需要实测佣兵模式确认。
- `instance_root`、`model_of`、`face_root` 里写死的 `"leon"` 回退改成按头部编号组取人。
- 界面：角色下拉和场景部件显示新角色名。

### 第二步：同伴与过场的识别补强（可选）

- 读 `get_PlayerAndPartnerContextList()`，角色列表给同伴加标记；同伴的根节点取自其 `BodyUpdater`，不再只靠网格路径向上找。
- 过场副本可从 `TimelineEventPuppetChara._HeadMesh` 直接取头部，减少对全场景网格扫描的依赖。只有第一步实测发现漏找或分组错误时再做。

### 第三步：逐个角色做表情标定

- 按需求排优先级：阿什莉 > 路易斯 > 佣兵模式三人（克劳萨、威斯克、汉克）。
- 每人一个 `builtin/re4/<id>.json`，做法同艾达：在游戏里取中立位快照（原生快照 / 录制工具），确定眼皮、下巴、嘴唇等面骨的轴和中立值，`Signals.validate` 校验；附带测试录制片段（`builtin/re4/recordings/<id>.json`）。
- 每完成一人，这个人自动从「表情未适配」变成完整驱动，不需要改代码。

## 测试

- 离线（`tests_re4r.lua` 夹具）：阿什莉头部被识别为角色、出现在 `actors()`；捏脸值写到她的网格；表情句柄为空且不读里昂的标定；玩家 context 返回阿什莉头部时她成为主角色；`actor_of("cha100_10") == "ashley"`。
- 游戏内：阿什莉跟随段（同伴）、阿什莉操作段、佣兵模式各角色、逆转篇艾达、带阿什莉的过场、模型鉴赏里的其他角色雕像。

## 影响

- 新增能力，按版本规范升 minor。
- 已有的里昂、艾达配置和绑定不受影响；新角色的绑定和配置放在各自的模型文件夹（`ashley/` 等）。
- AVM 联动：AVM 现在可以对七个人都调用 `select_group_option`，第一步之前对里昂、艾达以外的人会返回 `E_NOT_FOUND`。
