# RE9 头部形态键适配

首版支持 Resident Evil Requiem 的里昂默认主头部：自定义形态键手动控制、左右眨眼和张嘴三路基础自动表情，以及面板输入屏蔽。当前狂三 MMD 替换模型提供脸部形态键，本版不包含身体、头发通道或完整脸部自动映射。

运行时由 `reframework.get_game_name() == "re9"` 选择，沿用共用 Core、UI 和 Writer。原生资产、第三方模型、测试头部、用户设置及私有研究探针不随源码提交。

## 已完成范围

| 能力 | 当前结果 |
|---|---|
| 手动控制 | 默认头部测试键通过 0/0.5/1/0 分级控制；狂三模型识别 70 个名称、265 个通道项，闭眼和张嘴已验证全部同名索引写入与恢复 |
| 基础自动表情 | 左眨眼、右眨眼、张嘴三路；当前面骨优先模式已实机驱动，用户确认表情和眨眼正常 |
| 输入来源 | 保留原生修正优先的旧模式；另提供面骨优先、仅缺失项读取同名 Motion 骨姿态的模式 |
| 正式诊断 | 共用快照、录制和保存接口已修复，保留真实局部姿态、输入来源及标定配置 |
| 面板输入屏蔽 | 用户确认键鼠在面板打开时屏蔽游戏操作，关闭后正常恢复 |
| 生命周期与写保护 | 离线覆盖缓冲释放、头部重建、旧句柄失效、原生通道保护和持续写入；全部场景尚未验收 |

“识别到 70 个形态键”描述模型的输出通道；自动输入只有三路。手动控制不依赖为每个键提供自动映射。当前角色扫描只返回头部，身体、头发既未接入扫描，也没有实机验证。后续身体测试须使用实际带身体形态键的模型；VRC 来源本身不能证明具备这些通道。

## 对象、生命周期与写入

从当前 Scene 查找可见且有效的 `cp_A000`，有界遍历子树，选择资源路径为 `character/ch/ch01/0100/10/00/ch0100_10_00.mesh` 的唯一主头部。武器子树和名为 Shadow 的对象不参与扫描。

头部必须 MeshReady、BlendShapeEnable，且未释放缓冲。ChannelNum、WeightCount 和 ChannelWeightList 长度须有效，后两者不得小于通道数。适配器不分配权重缓冲、不修改 LOD。

身份签名包含场景、角色根、头部 Transform、Mesh 地址、骨架构建次数、通道数与缓冲边界。状态变化由共用 strict-bounds 路径在写入前释放旧目标，随后重新扫描和预热。信号句柄只保存名称、哈希、索引和身份数值，每次采样重新定位当前头部，不跨帧保存引擎关节或 Motion 对象。

通道名称通过 `get_ChannelNameHash().get_Item(i)` 和 UTF-16 Murmur3 名称表匹配。原生名称表、`_blendShape` 名称及未解析的 `#hash` 不可写；自定义通道写入前复核索引哈希和当前头部身份。公共 API、自动表情和捏脸均经过此限制。

权重由共用 Writer 在 LateUpdateBehavior 写入，调用时使用浮点 System.Single 参数。RE9 开启 `rewrite_active_weights`：当前或上次非零的权重持续重写，归零后可跳过重复的零到零写入。自动表情和手动捏脸使用相同策略。

## 三路自动输入

### 模式与兼容

| 模式 | 来源顺序 | 可读零值 |
|---|---|---|
| `legacy` | 原生修正通道；该语义所有原生来源均不可读时使用面骨 | 原生零值有效，不触发面骨回退 |
| `bones_first` | 真实面骨；缺失或不可读的测量项才读取 Motion 中同名骨姿态 | 面骨零值有效，不触发 Motion 回退 |

缺失输入分别退化，不取消其他有效输入，不累加两种来源，也不沿用上一帧输出。为保留原先行为，分发包缺省仍使用 `legacy`。当前实机已选择并验证 `bones_first`。用户可在真实数据目录的 `ShapeKeySystem/user/re9_input.json` 中选择：

```json
{"schema":"sks.re9-input/1","mode":"bones_first"}
```

修改后须 Reset Scripts；改为 `legacy` 可切回旧模式。无文件时使用旧模式，格式或模式无效时明确报错。用户模式文件不随分发包覆盖。

### 面骨与范围

`Bones.lua` 读取同一关节的 BaseLocalRotation 与 LocalRotation，对归一化四元数的相对旋转做轴投影，不修改骨骼姿态。

| 输入 | 测量 | 初始归一化范围 |
|---|---|---|
| eyeBlinkLeft / blink.L | 左上眼睑 X 角度减左下眼睑 X 角度 | 7..33.5° |
| eyeBlinkRight / blink.R | 右上眼睑 X 角度减右下眼睑 X 角度 | 12..34° |
| jawOpen | C_Jaw 的 X 角度 | 0.5..3° |

范围来自里昂场景的 379 个静止样本及 532 个有效动作样本，属于当前三路的初始标定。另 42 个头部未就绪样本未纳入统计。未套用其他游戏阈值，运行时也不根据极值动态扩大范围。对白、大幅张嘴与完整表情尚未标定；超出范围时输出封顶。嘴部区域增益保持用户现有的 0.57。

### 按需 Motion 回退

仅在 `bones_first` 中缺失测量项时，使用 getJointIndexByNameHash 和 getCalculatedLocalRotation 读取同名骨姿态。所需静止旋转随内置标定保存，并校验有效性。正常面骨齐全时不请求 Motion 姿态，不扫描全部动画参数。

同一轮缺失项共用局部采样会话。读取前后验证头部、Motion 所属对象、地址、骨架构建次数和关节数量；重建后旧索引不能沿用。无效四元数、身份变化及不可读项会明确退化。诊断需要时才额外读取局部位置。

这里补齐的是 Transform 中不可读、但 Motion 骨架仍保留的骨骼。若 Motion 中也没有该骨骼，则报告 `motion_joint_unavailable` 并将该路归零；尚未实现 RE4R 那样的动画资源分层采样。实机回退对照通过只读探针模拟缺失输入，没有删除模型骨骼，不能据此宣称实际无面骨模型已验收。

旧模式保留左、右 UprLdDn_00 原生修正，以及左右 JwOpn_00 的最大值，权重截断至 0..1。这些修正权重不等于完整面骨运动。`bones_first` 不将其混入面骨值，诊断可单独读取比较。

## 正式诊断与面板输入

正式快照的 `joints[name]` 现为真实局部位置与旋转组成的七项数值数组 `[px,py,pz,qx,qy,qz,qw]`，兼容共用 NativeSignals。静止姿态、结构化骨姿态、来源状态和实际标定分别保留，不用零位移或空关节表绕过接口要求。正常驱动不为诊断额外读取关节位置。

集成检查覆盖真实 Adapter 经过共用快照、录制、保存入口，以及保存失败后的保留与重试、头部身份变化后的录制结束。实机旧模式快照及 55 样本录制保存成功；面骨优先模式另完成 56 样本正式录制，五个关节的姿态均为七项数值。

`Input.lua` 使用 app.GameInputProvider 和 GameInputCondition.resetCondition()。面板打开时清除已保持的条件，每次游戏更新单个条件后再清除结果；仅在 hook 调用栈内持有临时对象。关闭与脚本重置后停止干预，等待键鼠及释放边沿结束再恢复游戏命令。

原生 HID 不清空，面板继续读取鼠标与键盘，必要时使用共用虚拟光标，与其他面板沿用共享输入屏蔽表。类型或方法不匹配时不启用 hook，并报告错误。正常里昂场景键鼠屏蔽和恢复已获用户确认，手柄保持输入尚未单独验收。

## 验证结果与限制

75 项 Adapter 和 18 项 Input 专项检查通过，90 个 Lua 文件语法通过。覆盖原生保护、同名通道全部索引写入、持续重写、手动与自动混合、有效零值优先、按缺失项回退、数值索引复用及重建失效，并覆盖正式诊断接口。

同步 1.7.0 后，全套与未修改基线均保留两项既有 gaze 失败，并因 RE4R mock 缺少 get_address 中断，后续测试组未运行。此前关于卡片的旧版本预期失败在新主线不再出现；全套仍不能报告为全部通过。

手动测试的 3256 个有效样本验证 `まばたき` 的四个索引及精确名称 `あ` 的五个索引均经过 0、约 0.5、1，最终归零；同名索引间最大差为零，用户确认闭眼、张嘴和恢复。早期误选的 `あ２` 单独保留，不代替 `あ` 的证据。

面骨优先启用前，593 个前台只读对照样本中，新旧模式三路输出一致；模拟缺骨后的同名 Motion 姿态输出最大差约 0.0000014。面骨齐全时 Motion 姿态请求始终为零。输入读取平均约 1.55 ms，旧模式约 1.62 ms，模拟全部缺失约 4.64 ms；这是观测器内的局部耗时，不是游戏帧率或通用性能承诺。

启用后的 549 个有效写入样本中，三路均由面骨提供，Motion 请求始终为零。左右眨眼各四个、张嘴五个索引共 7137 次读回比较，增益后最大误差小于 3×10⁻⁸，用户确认“表情以及眨眼看着都是OK的”。通用 MMD profile 使用 `ウィンク`、`ウィンク右` 和 `あ`，不需要模型专用 profile。

这些记录只覆盖当前狂三替换里昂的普通场景。连续采样数量不等于独立表情数量；固定姿态全零的早期记录不计入自动驱动通过证据。过场、读档、服装状态及其他角色未因此获得验收，整张脸的标定也尚未完成。

## 与 RE4R 的差距

对照主线的 RE4R 适配器、内置数据及共用接口；本轮同步的 1.7.0 主线没有修改 RE4R 实现。RE4R 自身也保留更多场景组合的后续验证，以下描述功能实现范围。

| 项目 | RE4R | RE9 首版 |
|---|---|---|
| 自动映射 | 63 项字典中 39 项有映射 | 仅三路；距离 RE4R 还差 36 项已映射语义，不能以模型键数代替 |
| 眼球视线 | 眼球旋转，缺失时可从 Motion 补充 | 未读取眼球或输出实时视线 |
| 禁用骨骼表情 | 固定指定表情骨，读取固定前动画姿态 | 未接入；无面部顶点权重 addon 只是当前模型方案 |
| 缺失输入 | 面骨、原生修正与动画资源补齐 | 保留旧模式，新增同名 Motion 骨姿态回退；资源采样仍缺失 |
| 过场 | 时间线状态、重建通知及驱动开关 | gate 仅判断头部就绪，尚未响应共用面板的过场驱动开关 |
| 角色与部件 | Leon、Ada、指定服装和额外实例；可扫描更多部件 | 仅 cp_A000 默认 10/00 主头部；身体、头发、Grace、其他服装及多实例均未接入 |
| 状态条件 | 战斗、移动、瞄准、换弹、伤害及生命状态等 | 没有 conditions 采样接口 |
| 正式诊断 | 共用快照、中立位及录制保存 | 已修复快照契约并实机验证快照与录制保存 |
| 录制回放 | 通过当前 Profile 回放并提供内置片段 | 没有 playback 接口；研究 JSON 不等于可直接回放的文件 |

当前核对的里昂 Transform 关节库存没有发现荒野 fcParam_* 或鬼武者 bsControl_* 那样的整组参数关节，不据此推断所有 RE9 角色。资源研究确认 96 项原生修正参数与 32 项皱纹参数；狂三替换后的只读研究也取得 356 个有效样本和活动口型控制器读数。这些是后续来源候选，不是已接入的自动映射。全量研究读取耗时不用于推断按需 Motion 回退成本。

## 后续补齐顺序

1. 盘点剩余语义的真实输入：眼球、眉毛、眼睑、嘴角和口型。逐项标明面骨、按需 Motion 或尚无可靠来源，继续保持面骨优先。
2. 分组接入与标定：眼球视线及眼部、眉毛和嘴角、其余口型。张嘴幅度不能直接推导多种元音，不能只用形态键别名填满映射表。
3. 涉及过场前补上时间线状态、驱动开关与对象切换处理，再用清晰对白和明显表情标定，用独立片段检验；另测结束、跳过与读档。
4. 按需扩展禁用骨骼表情、真正无面骨资源回退、身体头发、服装、Grace、多实例、状态条件及回放。身体测试先核实源模型和导出部件实际带键，再单独安装与验收。

本版用于保存已确认可用的头部能力，不是与 RE4R 完整对齐的版本，也不调整共用版本号或替代第三方模型包。
