# RE9 头部形态键适配（实验性）

RE9 当前属于实验性适配。本版支持里昂默认主头部的自定义形态键手动调整，以及普通游戏场景中的头部自动表情。过场、其他角色和部件、真正无面骨模型等仍有未完成项，不能视为 RE9 完整支持。

运行时按 `reframework.get_game_name() == "re9"` 选择独立适配器，共用 Core、UI 和 Writer。RE4R 只用于共用接口参考；接入范围由 RE9 实际可读的输出决定，不以其他游戏的映射数量作为完成指标。

## 已实现范围

| 能力 | 当前范围 |
|---|---|
| 手动捏脸 | 调整默认主头部中可解析、允许写入的自定义形态键；同名的多个索引一起写入 |
| 基础自动表情 | 左右眨眼、下颌张嘴 |
| 头部扩展 | 眉毛、眼睑、鼻颊、上下唇、嘴角、横拉收拢、嘴部左右移动和下巴上提 |
| 眼球视线 | 读取眼球相对旋转；当前模型的上下视线输出已有普通场景动态记录 |
| 口型基形 | 从下颌、嘴角和上下唇估计 RE9 原生 A／I／U／E／O 形状，按模型接收键匹配 |
| 输入回退 | 有效面骨优先，缺失测量项才按需读取同名 Motion 骨姿态 |
| 诊断 | 共用快照、录制和保存，保留实际姿态、来源及标定配置 |
| 面板输入屏蔽 | 保留普通游戏场景的命令屏蔽和释放等待；菜单光标、左键仍有穿透 |

手动控制不要求为每个键建立自动映射。形态键必须正确导出，并有可解析的名称；未解析哈希名和游戏原生受保护通道不开放写入。当前狂三模型只有脸部形态键，不能由此推断身体或头发已接入。

## 安装、默认配置与兼容

安装需要 REFramework 和实际带自定义形态键的模型／名称表。MMD 模型首次使用时，在面板选择 **RE9 MMD**；ARKit 等其他命名模型选择对应配置。适配器不替换共用系统的全局 Profile 默认值，也不覆盖用户已经选择的 Profile。

本版首次安装默认采用 `bones_first` 并开启头部扩展。已有 `ShapeKeySystem/user/re9_input.json` 时继续优先使用该文件：

| 输入配置 | 实际行为 |
|---|---|
| 没有用户覆盖文件 | 面骨优先，扩展开启 |
| 已有 `mode: legacy`，没有 `extended` | 保留旧原生修正优先模式，扩展关闭 |
| 已有 `mode: bones_first`，没有 `extended` | 保留原三路面骨模式，扩展关闭 |
| 明确指定 `extended: true` 或 `false` | 遵从用户选择，不随更新翻转 |

已有安装要启用本版全部头部扩展，可在游戏真实数据目录的 `reframework/data/ShapeKeySystem/user/re9_input.json` 中使用：

```json
{"schema":"sks.re9-input/1","mode":"bones_first","extended":true}
```

修改后 Reset Scripts。要保留旧原生修正优先行为，可改为 `mode: legacy`、`extended: false`。无效配置会明确报错，不悄悄替换为默认值。发布包不附带或覆盖用户的 settings、user、mods、名称表及私人增益；模型专用名称表由对应模型包提供。

## 自动表情的含义与边界

面骨测量读取同一关节的 BaseLocalRotation／LocalRotation 或 BaseLocalPosition／LocalPosition，使用固定角度和毫米范围归一化。原有十四路标定保留，新加入二十七路输入及五种口型基形。运行时不根据采样极值自动扩大范围。

口型基形以八项下颌、嘴角和上下唇测量共同估计混合权重，是口型形状估计，不是音频音素识别。RE9 MMD 为相应元音键提供映射，并减弱同时出现的基础张嘴、横拉或收拢，减少重复叠加。当前狂三具有这些接收键；缺少元音键的其他模型须另行核对配置和形变效果。

九十六项原生 HeadSkinned 修正以 `re9.native.<suffix>` 保留名称，供显式绑定。面骨路径是成对原生轨道拟合得到的初始估计，不等于直接读回的原生标量；其中包含组合修正，默认不全部叠加到 MMD。拟合保持原点为零，尚无独立片段或实机标量的逐项对照。三十二项皱纹参数按材质输出理解，不作为额外面部形变。

眉毛内收暂用保守范围，眉心上提等未触发输入仍不能标为完整幅度标定。声明了输入或出现非零值，不等于每个表情语义已准确还原。

## 面骨优先与按需回退

`bones_first` 中，有效面骨零值就是有效输入，不触发 Motion 回退。只有缺失或不可读的测量项才读取同名 Motion 骨姿态；同一轮同一关节的同类姿态共用数值缓存，不跨帧保留姿态或引擎关节对象。静止旋转及需要的位置随标定保存。

读取前后验证当前头部、Motion 所属对象、地址、骨架构建次数和关节数量；重建后旧索引不能沿用。缺失项各自退化，不取消其他输入、不累加两种来源，也不沿用上一帧输出。眼球失效时返回用户中立位，避免留下旧方向。

配置了明确原生参数来源的投影，在同名骨姿态也不可用时可按需读取对应原生 Motion 参数 X 值，不扫描全部参数。默认诊断不包含九十六项显式修正。真正无面骨模型下的完整动画资源采样回退尚未实现或验收。

`legacy` 保留原生修正优先的行为：有效原生零值不回退；该语义所有原生来源均不可读时使用面骨。当前推荐并实测的普通场景配置为 `bones_first`、扩展开启。

## 对象、写入和生命周期

正式定位仅覆盖可见、有效的 `cp_A000` 及资源为 `character/ch/ch01/0100/10/00/ch0100_10_00.mesh` 的唯一默认主头部。武器子树和 Shadow 对象不参与扫描，当前不扫描身体、头发、Grace、其他服装或额外演员实例。

写入前要求网格就绪、权重缓冲未释放，通道数、WeightCount 和列表长度有效。适配器不分配权重缓冲，不修改 LOD。身份包含场景、角色根、头部、Mesh、骨架构建次数、通道数和缓冲边界；变化后释放旧目标，重新扫描和预热。

名称通过通道哈希与名称表匹配。原生名称、`_blendShape` 和未解析的 `#hash` 受写保护；每次自定义通道写入复核索引哈希与当前头部身份。

自动与手动权重均由共用 Writer 在 LateUpdateBehavior 写入，参数使用 System.Single 浮点值。RE9 持续重写当前或上次非零权重，以应对游戏每帧清零；归零后可跳过重复零值写入。

正式诊断保存真实局部位置和旋转组成的七项数组及结构化姿态；正常驱动不为诊断额外读取位置。快照、录制、保存失败重试和身份变化后的录制结束均有专项检查。

## 验证结果

当前提交候选通过 134 项 Adapter、18 项 Input 检查；默认策略覆盖首次安装、旧文件缺省字段、明确启用／禁用和无效配置，输入实现及输入测试与已提交版本一致。源码通过 Lua 语法检查，安装包另作文件清单和哈希回读，不将这些离线结果当作新增实机验证。

当前狂三识别 70 个名称、265 个通道项。手动记录验证闭眼和精确名称「あ」的全部重复索引经过分级变化并最终归零，用户确认可见效果。

整批普通场景记录取得 1085 个连续就绪样本、一个头部身份，29 个模型形态键权重发生变化。279930 次接收索引比较一致，最大误差小于 3×10⁻⁸；按每段固定开头两秒单列后，1067 个样本、275286 次比较仍一致。面骨及眼球观测中的 Motion 请求为零，用户确认前台走动、短跑时眨眼和张嘴正常，无明显歪斜或拉扯。

同名 Motion 骨姿态回退另有模拟缺失对照，没有删除模型骨骼。当前无面部顶点权重 addon 仍保留可读骨骼，不能据此宣称真正无骨模型通过。原生轨道回放和固定姿态样本也不替代动态画面验证。

共用全套测试仍有主线已知 gaze 失败，并因既有 RE4R mock 缺少 get_address 中断，后续组未运行；不能报告全套通过。带观测器时的 Core tick 窗口均值约 11.43 ms，不是纯输入耗时或游戏帧率，性能仍需独立比较。

## 打包与交付范围

本版为实验性开发候选，不提升共用版本号，不冒充上游正式发布。源码包遵从仓库现有文件清单；本项目审阅包从干净目录生成，再核对每个文件的哈希和 ZIP 内容，避免旧 stage 遗留已撤回模块。

包内保留运行所需 Lua、内置数据、资源及第三方声明；不包含菜单实验、私有研究探针、测试头部、原生游戏资产、第三方模型、用户设置、用户名称表和采样记录。当前游戏安装不因生成审阅包而自动更新。

菜单实验及测试脚本保留在项目历史资料中。当前提交恢复已提交的 Input.lua，不包含未通过的 MenuInput 或全量 GUI 控件扫描。

## 已知问题与后续工作

- 背包、地图或暂停菜单中，光标和左键仍可穿透 SKS，右键不响应；按用户要求暂缓。全量逐帧 GUI 控件扫描曾造成严重掉帧，已撤回，用户确认回滚后恢复正常。
- 正式 gate 只判断主头部就绪，尚未响应过场驱动开关；CG 演员选择与切换、结束、跳过、读档后的生命周期处理仍待接入。私有定位器不是正式 CG 支持。
- 对白口型准确度、独立 CG 对照、未触发表情及其他接收模型尚待标定和验证。
- 完整缺骨模型的资源回退、禁用原生面骨表情功能、更多角色服装实例、身体头发、状态条件和回放属于后续扩展。

下一阶段优先补正式 CG 生命周期与对白验证。身体测试先检查实际模型和导出部件是否带形态键，不按模型来源推断。
